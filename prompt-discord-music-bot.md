# Промпт для Claude Opus 5: Discord музыкальный бот

Скопируй всё ниже и вставь в чат с Opus 5.

---

Ты — опытный backend-разработчик, специализирующийся на Discord-ботах (discord.js v14) и потоковом аудио. Помоги мне создать полноценного production-ready Discord-бота для воспроизведения музыки.

## Технологический стек

- **Node.js** (LTS) + **discord.js v14**
- **@discordjs/voice** + **@discordjs/opus** для голосовых соединений
- **ffmpeg** (через `ffmpeg-static` или системный)
- Источники аудио:
  - **YouTube**: `play-dl` или `yt-dlp` (через дочерний процесс) — предпочтительно yt-dlp, он стабильнее держит совместимость при изменениях YouTube
  - **Spotify**: `spotify-web-api-node` — ТОЛЬКО для получения метаданных (название, исполнитель, альбом, длительность). Сам аудиопоток брать нельзя (DRM), поэтому по названию+исполнителю ищем и стримим совпадающий трек с YouTube
  - **SoundCloud**: `play-dl` (умеет SoundCloud из коробки) или `soundcloud-downloader`
- Хранение очередей — в памяти (Map по guild.id), с возможностью потом заменить на Redis
- Регистрация команд — **slash commands** (не текстовые с префиксом)

## Функциональность

Команды:
- `/play <запрос или ссылка>` — играть трек/плейлист (YouTube-ссылка, Spotify-ссылка/URI, SoundCloud-ссылка, либо просто текстовый запрос → поиск на YouTube)
- `/pause`, `/resume`, `/skip`, `/stop`
- `/queue` — показать очередь (с пагинацией, если треков много)
- `/remove <позиция>` — убрать трек из очереди
- `/shuffle` — перемешать очередь
- `/loop <off|track|queue>` — режимы повтора
- `/volume <0-100>`
- `/nowplaying` — текущий трек с прогресс-баром
- `/seek <время>` — перемотка (если источник поддерживает)
- `/join`, `/leave`

UX:
- Embed-сообщения с обложкой трека, названием, исполнителем, длительностью
- Кнопки под сообщением (пауза/скип/стоп/повтор) через `ButtonBuilder` + `ActionRowBuilder`
- Автоматический выход из голосового канала при пустом канале (через `voiceStateUpdate`) и при пустой очереди (таймаут ~2-5 мин)
- Поддержка плейлистов (YouTube playlist, Spotify playlist/album) — добавление всех треков в очередь одним вызовом

## Архитектура

Опиши и реализуй:
1. Структуру проекта (папки `commands/`, `events/`, `structures/` или `services/`, `utils/`)
2. Per-guild менеджер очереди (класс `MusicQueue` или похожий): текущий трек, массив следующих, состояние плеера, volume, loop-режим, привязанный `AudioPlayer` из `@discordjs/voice`
3. Единую абстракцию `resolveTrack(query)`, которая определяет тип источника по ссылке/тексту и возвращает нормализованный объект трека (title, url, duration, thumbnail, streamProvider), не завязываясь в остальном коде на конкретный источник
4. Обработку ошибок: недоступное видео, приватный плейлист, бот не в голосовом канале, разрыв соединения, rate limit YouTube — с понятными сообщениями пользователю, без падения процесса
5. Систему деплоя slash-команд (глобально и/или для тестового сервера через `guildId`)

## Конфигурация

- `.env` для токенов: `DISCORD_TOKEN`, `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`
- `config.js`/`config.json` для настроек (макс. длина очереди, таймаут авто-выхода, дефолтная громкость)

## Формат ответа

1. Сначала — краткий план архитектуры (список файлов и их назначение)
2. Затем — код по файлам, с комментариями на русском/английском (уточни, на каком языке комментировать)
3. В конце — инструкция по установке зависимостей, получению токенов (Discord Developer Portal, Spotify Developer Dashboard) и запуску (включая установку ffmpeg и yt-dlp)
4. Если что-то технически невозможно или требует компромисса (например, точный seek на YouTube-потоке) — явно предупреди об этом, а не делай вид, что всё работает идеально

Начни с шага 1 — структуры проекта и списка файлов, а полный код пиши по частям, чтобы я мог проверять каждый модуль перед переходом к следующему.
